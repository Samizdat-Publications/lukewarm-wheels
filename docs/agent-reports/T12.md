That returned the full versions table. Colour, tampo, base colour/type, window colour,

## Catalog

Field names are unchanged (`id … livery`, `HW.wheelTypes`, `HW.catalogById`) so the physics
keeps reading it. Two additions: `entry.body` (silhouette description for the mesh builder)
and `HW.pack` (pack name / year / toy number, for the showroom). `HW.wheelTypes` radii were
tightened: 5DOT 0.48 → 0.50, SB 0.60 → 0.55 cm; crr values unchanged. All widths stay in
2.3–2.6 cm so the foam-nip squeeze (`width − 2.0`) stays in range.

## Mesh builder

`buildMesh(entry)` returns a `THREE.Group` whose origin is the chassis centre, matching the
physics cuboid (length on Z, −Z the nose). Per car: an extruded side-profile lower body
(nose → hood drop → beltline → deck → tail), an extruded greenhouse, side/windscreen/
backlight glass with the catalog tint, an interior block seen through the glass, a base
plate (metal = light grey metallic, black = plastic-look), an optional pickup bed or rear
wing, and four wheels with a canvas-drawn rim face per wheel code (5SP spokes, 5DOT holes,
3SP wide spokes, SB saw-blade notches).

Liveries are two `CanvasTexture`s per car (a side elevation and a top view), painted from
`entry.livery` and applied through `MeshStandardMaterial` (metalness 0.6, roughness 0.35).
UVs are re-projected after extrusion so both the lower body and the cabin sample the correct
region of the same full-car texture; `u` is mirrored on the +X flank so text reads
nose-to-tail on both sides, and roof/hood text is drawn rotated so it reads from above.

`group.userData.wheels = [FL, FR, RL, RR]` (FL = −X, −Z, matching `42-vehicle.js`).
`sync(car, group)` spins the wheels from `car.wheelState(k).rot` and, when the controller
reports a suspension length, settles their height; body position/orientation stay the
renderer's job. `collectorCard(entry)` returns an HTML string for the showroom (T15).

## Verified

- `node -e "… require('./src/20-catalog.js')"` loads clean; all five widths in band.
- Preview page at `http://localhost:8765/tools/cars-preview.html`: **0 console errors**
  (one unrelated three.js deprecation warning for `PCFSoftShadowMap`).
- **2104 triangles for all five cars (≈421 per car)** — far under the ~3000/car budget.
- Mesh bounding boxes match the physics cuboid exactly in length and width; height and
  width exceed it only by the wheels, which hang `carClearance` (0.3 cm) below the chassis
  and sit ~0.8 mm proud of the flanks, as real castings do. `bevelOffset: -bevelSize` in
  `extrudeProfile` is what keeps the body from growing past the collider — do not remove it.
